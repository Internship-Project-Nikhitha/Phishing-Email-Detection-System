# Public Email Dataset Research

**Research checked:** 2026-10-21 (recommended candidate metadata rechecked). This is a source-document review, not a legal opinion or a download/forensic audit of the corpus files. Source facts are separated from project assessments. A claim absent from a source is marked unknown rather than inferred.

## Decision

The Kaggle **Phishing Email Detection** CSV, available as a public Hugging Face mirror, is the only investigated candidate that directly advertises both phishing and safe email-body categories and an explicit dataset license. It is the recommended *conditional research candidate*, not an unconditional redistribution recommendation. The Kaggle creator and Hugging Face mirror state LGPL-3.0, which ordinarily permits commercial use, modification, and redistribution subject to its terms; however, the dataset card points to a user-uploaded Kaggle copy and does not establish who collected the original email messages or whether the uploader had authority to license all message text. Review the corpus and applicable rights before commercial deployment or redistribution. If that uncertainty is unacceptable, seek permission or select a corpus whose original publishers clearly license the messages and annotations; none of the other inspected sources was a direct, licensed binary phishing/legitimate email dataset.

The repository does not automatically download, combine, or redistribute any corpus. Label mapping is explicit and exact stored values must be checked locally before training.

These are six public dataset candidates/sources found in this review. Three Kaggle listings claim both target categories, but only one provides a source-described body/label schema and HF-reported row count. None has fully verified original email-content rights and independently validated label quality. Therefore, this review cannot honestly designate three candidates as fully suitable under the user's strict provenance/license/label verification criteria. Nazario is a high-relevance phishing-only corpus; SpamAssassin and Enron are not relabeled as phishing/legitimate. No dataset is combined with another here.

## Candidate Findings

### Kaggle/Hugging Face phishing email CSV

The Kaggle page calls the dataset **Phishing Email Detection**, attributes the upload to Kaggle user Cyber Cop (`subhajournal`), and describes email body text and an email-type field. Its current metadata does not state the exact stored labels or define the non-phishing class. Kaggle declares LGPL-3.0; the Hugging Face mirror describes itself as a direct copy, also claims LGPL-3.0, identifies English, and points back to Kaggle. Hugging Face API metadata at revision `34085a032c123ca237f314a01a67909cdea35e34` reports one `train` split with 18,650 records and three columns. Field names `Unnamed: 0`, `Email Text`, and `Email Type` have been reported for the CSV but were not verified against a downloaded file. These are source/mirror claims, not independent content validation.

Advantages: phishing-focused title, email-body/type description, public ungated mirror, reported CSV format and row count, and an explicit license declaration. Disadvantages: the reviewed source metadata does not verify that the labels mean phishing versus legitimate; Kaggle-origin provenance is not traced to original collectors; and no annotation protocol, source-level lineage, class counts, duplicates, missingness, or campaign metadata are documented. Exact headers and values in the label column have not been checked because no data file was downloaded. The LGPL declaration's applicability and upstream rights in message contents, personal data, and malicious URLs remain unresolved. A license claim on a mirror does not by itself prove authority over third-party email content.

### Nazario

The maintainer's README says this is a personal inbox, hand-classified, representative rather than exhaustive, and potentially error-prone. It explicitly states CC BY 4.0 and describes anonymization as incomplete in later mailboxes. The index lists older mbox files and yearly folders, but does not provide a verified total record count or language profile. This is valuable phishing-only research material, not a standalone binary training set.

### SpamAssassin

The official README provides archive layout, a dated revision history, category sizes, and a 6,047-message total. It explains spam versus non-spam, not phishing versus safe. Some messages were de-duplicated and a misclassified example was removed. Its old date range, residual label noise, full headers, and sender copyright make it unsuitable as a drop-in labeled target and potentially unsuitable for redistribution.

### Enron

The CMU page describes a corpus prepared by the CALO project from data made public during the FERC investigation, with about 0.5M messages from about 150 users. It notes redaction requests and modified/invalid address handling and expressly raises privacy sensitivity. It has no task labels and no explicit license in the reviewed page, so it is excluded from binary training and redistribution absent additional permission and labeling.

### Other Kaggle binary claims

The Kaggle API lists `akileshga/email-phishing-legitimate-classifier` with a declared Apache 2.0 license and one 830,836-byte CSV, but the page metadata does not disclose its schema, row count, exact labels, collection source, or annotation method. It is a promising alternative to request/inspect, not a currently verified choice.

`naserabdullahalam/phishing-email-dataset` declares CC BY-SA 4.0, says it combines Enron, Ling, CEAS, Nazario, Nigerian Fraud, and SpamAssassin datasets, and claims approximately 82,500 messages. Its description treats some spam labels as phishing and cites two papers. The class counts shown (42,891 + 39,595) sum to 82,486, not exactly 82,500. The aggregate's individual components, rights, mappings, and label consistency are not established by the Kaggle metadata. Do not assume the umbrella license applies to all message content or that spam means phishing; do not combine it with other datasets without per-source compatibility review.

## Integration Policy

- Keep the source data outside version control. `data/` and model artifacts are ignored by `.gitignore`.
- Inspect only label values and aggregate counts before training; do not print message contents.
- Configure exact source column names and label strings. The loader never guesses or aliases a source label.
- Preserve subject/body indicators, URLs, HTML, and headers when present; only empty text, unknown labels, malformed values, conflicting-label exact duplicates, and configured exact duplicates are excluded.
- Run `python -m src.data.validate_dataset ...` and review its aggregate report and redacted invalid-row reasons before training.
- Default train/test evaluation is random and stratified when class counts allow. If source/campaign groups exist, use `--group-column` to hold those groups out. A group split can reduce known overlap but cannot detect unknown campaigns or time/source effects.

Quality checks reduce risk but cannot guarantee no leakage, no personal information, representative sampling, valid labels, or real-world performance. Human review and a current, independently sourced external test set are needed before operational use.
